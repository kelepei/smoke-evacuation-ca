行人疏散仿真平台系统架构

1. 项目概述

项目名称：

烟雾风险感知与社会信息传播耦合的行人疏散元胞自动机模型及仿真平台

本平台用于构建地图、设置人员属性，并基于元胞自动机（CA）模型进行行人疏散仿真，同时考虑烟雾风险感知和社会信息传播对人员行为的影响。

平台整体由四个主要模块组成：

A：地图与场景模块

B：元胞自动机（CA）仿真模块

C：人员与行为属性模块

D：平台界面与可视化模块

用户进入平台

      ↓
地图导入与转换
      ↓
地图人工编辑
      ↓
语义区域标注
      ↓

      ↓
保存当前地图
      ↓

      ↓
系统自动分配人员初始位置
      ↓

      ↓

4. A：地图与场景模块

A 负责平台中的地图数据处理。

主要功能：

CSV/JSON 网格地图导入；

PNG/JPG 图片地图导入；

图片二值化；

地图解析；

地图人工编辑；

语义标签；

场景模板；

人员初始位置分配。

地图最终统一转换为 Grid。

5. B：CA 元胞自动机仿真模块

B 是平台的核心仿真模块。

主要负责：

CA 网格读取；

人员状态读取；

邻域搜索；

人员移动决策；

目标出口选择；

多人冲突处理；

同步更新；

疏散过程模拟；

烟雾影响；

风险影响；

社会信息传播；

疏散结果计算。

基本输入：

地图 Grid
+
带初始位置的人员 JSON
+
场景参数

基本输出：

每个时间步的人员状态
+
烟雾状态
+
疏散统计结果

B 不需要处理 PNG/JPG 等原始地图格式。

6. C：人员与行为属性模块

C 负责生成和管理人员数据。

人员数据主要包括：

id
x
y
speed
group_id
profile
risk_sensitivity
familiarity
herding_tendency
target_exit
info_state
evacuated
dose

其中：

profile：人员类型；

speed：移动速度；

group_id：所属群体；

risk_sensitivity：风险敏感程度；

familiarity：环境熟悉程度；

herding_tendency：从众倾向；

info_state：信息状态；

evacuated：是否完成疏散；

dose：烟雾暴露相关状态。

C 输出人员 JSON。

例如：

output_people.json

人员属性设置完成后，由位置分配模块根据当前地图自动确定初始 x/y。

当前地图 JSON
       +
人员属性 JSON
       ↓
position_allocator.py
       ↓
人员初始位置

位置分配主要依据：

profile
+
semantic
+
group_id

同时保证：

位置在地图范围内
位置对应 free 元胞
不同人员不能占用同一元胞
同组人员尽量靠近

该模块主要修改：

x
y

人员的其他属性保持不变。

13. A → B 接口

人员位置分配完成后生成：

people_with_positions.json

完整流程：

地图编辑完成
      +
人员属性设置完成
      ↓
position_allocator
      ↓
people_with_positions.json
      ↓
interface_validator
      ↓
B CA 模型

因此 B 最终读取的是：

地图数据
+
people_with_positions.json

而不是直接读取 PNG 或 JPG。

16. 烟雾风险模块

烟雾模块用于描述烟雾随时间和空间变化的状态。

地图元胞可以记录：

smoke

人员可以记录：

dose
risk_sensitivity

基本关系：

烟雾浓度
   ↓
人员暴露
   ↓
风险感知
   ↓
移动决策

烟雾风险会进一步影响人员的疏散行为。

17. 社会信息传播模块

人员之间通过社会关系传播疏散信息。

相关人员属性包括：

group_id
herding_tendency
familiarity
info_state

基本流程：

人员获得信息
      ↓
向附近人员传播
      ↓
其他人员更新信息状态
      ↓
影响其风险判断
      ↓
影响移动/出口选择

该模块与烟雾风险感知共同影响 CA 中的人员决策。

22. 核心设计原则

统一数据结构

所有地图最终统一为 Grid，所有人员最终统一为人员 JSON。

模块解耦

A、B、C、D 通过统一接口交互，不直接依赖其他模块的内部实现。

用户驱动

最终平台不要求用户手动选择中间文件。

用户完成：

地图编辑
+
人员属性设置

之后，由平台自动完成：

地图保存
→ 人员位置分配
→ 接口校验
→ CA初始化
→ 开始仿真

输入与仿真分离

原始 PNG/JPG/CSV 等文件只用于生成地图，不直接参与 CA 计算。

CA 模型只使用统一后的地图和人员数据。

24. 架构目标
